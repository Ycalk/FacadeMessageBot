# MAX Facade Message Bot

Бот для мессенджера MAX, позволяющий пользователям отправлять текстовые сообщения, которые после модерации отображаются на медиафасаде здания через интеграцию с API подрядчика.

## О проекте

Проект представляет собой микросервисную архитектуру для обработки пользовательских сообщений с многоуровневой модерацией перед публикацией на физическом медиафасаде. Пользователи взаимодействуют с ботом в мессенджере MAX, вводят свое сообщение, имя и город, после чего сообщение проходит несколько этапов проверки, после которых показывается на фасаде. После показа пользователю приходит сообщение с фотографией послания на фасаде.

## Стек технологий

### Backend
- **Python** — основной язык разработки
- **FastAPI** — REST API
- **FastStream** — асинхронное взаимодействие с RabbitMQ
- **RabbitMQ** — брокер сообщений между сервисами
- **Tortoise ORM** — PostgreSQL
- **Redis** — кеш состояний и хранения
- **Elasticsearch** — быстрый поиск городов
- **Aiogram** — Telegram-бот
- **Mistral AI** — автоматическая модерация
- **Docker & Docker Compose** — контейнеризация
- **Sentry** — мониторинг ошибок
- **PaddleOCR** - распознование текста с видео потока

## Архитектура микросервисов

Проект состоит из следующих сервисов:

### **bot** (`services/bot`)
Бот для пользователей MAX: сбор текста, имени и города, управление состояниями (FSM), отправка данных на модерацию.

### **auto_moderator** (`services/auto_moderator`)
Автоматическая модерация: проверка через черный список и Mistral AI, фильтрация сообщений.

### **manual_moderator** (`services/manual_moderator`)
Telegram-бот для подтверждения или отклонения сообщений.

### **table_moderator** (`services/table_moderator`)
Коллективная модерация через Google Sheets: сообщение попадает в таблицу, решение принимает команда вручную.

### **media_facade** (`services/media_facade`)
Интеграция с MAER API: получение конечного одобренного сообщения и передача для показа на фасаде, обратная связь через webhook о статусе.

### **vision** (`services/vision`)
Видеоаналитика фасада: захват видеопотока, обработка кадров (FFmpeg, PaddleOCR, OpenCV), опознание отображенного сообщения и автоматическая отправка фото пользователю, когда его контент появился на фасаде.

### **black_list_bot** (`services/black_list_bot`)
Бот для администрирования черного списка слов, интеграция с Redis.

### **cities** (`services/cities`)
API для поиска городов пользователя и поддержки автозаполнения адреса.

### **shared_models**
Общие Pydantic-схемы, структуры очередей, enums, общая инфраструктура для микросервисов.

## Схема обработки и переходов

```
Пользователь → bot 
  ↓
auto_moderator
  ↓
manual_moderator
  ↓
table_moderator
  ↓
media_facade
  ↓
vision → фотоотчет пользователю
```

## Особенности реализации

### **bot** (Основной MAX бот)

**Назначение:** Главная точка входа для пользователей в мессенджере MAX

**Ключевые особенности:**

- **State Machine на Redis:** Управление состояниями пользователя (FSM) с поддержкой персистентности между перезапусками, поддержка in-memory режима для тестирования
- **City Extractor:** Две стратегия поиска городов по тексту - через Elasticsearch API и fuzzy matching (thefuzz). Возможность извлечение города из GPS-координат через Nominatim OSM API
- **Name Validator:** Валидация имен через белый список и внешний Name API с проверкой уверенности (confidence)
- **Система лимитов:** Контроль количества попыток на сообщение, общего количества сообщений на пользователя, тайм-аута между отправками
- **Webhook уведомления:** Получение результатов модерации и подтверждений показа через RabbitMQ, отправка фото с фасада пользователям
- **MAX API библиотека:** В ветке `bot` используется кастомная библиотека `aiomax`, в новых версиях - полуофициальная `maxapi`

***

### **auto_moderator** (Автоматическая модерация)

**Назначение:** Первый уровень проверки контента

**Ключевые особенности:**

- **BlackList с FlashText:** Быстрая проверка на запрещенные слова через KeywordProcessor, хранение в Redis с автоматической синхронизацией
- **Mistral AI модерация:** Анализ по категориям с настраиваемым порогом одобрения
- **Маршрутизирование:** Одобренные сообщения отправляются на ручную модерацию, отклоненные - напрямую пользователю с причиной

***

### **manual_moderator** (Ручная модерация через Telegram)

**Назначение:** Второй уровень проверки контента человеком

**Ключевые особенности:**

- **Модераторы и администраторы:** Разделение ролей с разными правами доступа, хранение в Redis
- **Статистика модераторов:** Отслеживание количества обработанных сообщений, последней активности, статуса активности
- **Таймауты неактивности:** Автоматическое снятие сообщения с модератора при превышении времени обработки
- **Режим автоодобрения:** Позволяет автоматически одобрять все сообщения для тестирования
- **ModerationLoop:** Асинхронный цикл распределения сообщений между активными модераторами с балансировкой нагрузки по messageid

***

## **table_moderator** (Коллективная табличная модерация)

**Назначение:** Третий уровень проверки через Google Sheets

**Ключевые особенности:**

- **Google Sheets интеграция:** Использование aiogoogle с Service Account для автоматизации работы с таблицами
- **Protected Ranges:** Защита служебных столбцов (ID, текст, имя, город, обработано) от редактирования модераторами
- **Командное голосование:** Конфигурируемое количество команд (по умолчанию 3), каждая команда имеет два столбца - "Одобрить" и "Отклонить"
- **Логика принятия решений:** Отклонение срабатывает мгновенно при хотя бы одном отрицательном голосе любой команды; одобрение требует согласия всех команд
- **Автоматическая разметка:** После обработки строка помечается как "TRUE" в столбце "Обработано", блокируется через Protected Range и окрашивается серым цветом
- **Data Validation:** Автоматическое создание checkbox'ов для голосования через Google Sheets API
- **UpdateLoop:** Постоянный polling таблицы каждые 5 секунд для обнаружения новых решений модераторов

***

## **media_facade** (Интеграция с MAER API)

**Назначение:** Финальная отправка одобренных сообщений на фасад

**Ключевые особенности:**

- **MAER API интеграция:** REST API клиент для отправки сообщений подрядчику через httpx
- **Webhook endpoints:** Прием обратных вызовов от MAER о результатах модерации и подтверждении показа
- **Mock-режим:** Встроенный эмулятор MAER API для разработки и тестирования без реального фасада

***

## **vision** (Видеоаналитика фасада)

**Назначение:** Автоматическая фотофиксация показанных сообщений

**Ключевые особенности:**

- **Многопроцессный захват видео:** FFmpeg reader в отдельном процессе для стабильного захвата RTMP-потока с обработкой буферизации
- **PaddleOCR распознавание:** Использование PP-OCRv5 mobile моделей (детекция + распознавание) для извлечения текста с кадров
- **Frame Processor:** Обработка видеопотока с preprocessing'ом (crop 9:16, scale 800x1340), распознавание текста каждые 0.5 секунды
- **Frame Matcher:** Fuzzy matching через thefuzz для сопоставления распознанного текста с ожидаемыми сообщениями
- **Redis Storage:** Хранение кадров (base64) и метаданных сообщений с индексацией по временным меткам через ZSET
- **Автоочистка:** Удаление старых изображений и неотправленных сообщений после таймаута (по умолчанию ANALYTICS_DELAY + 2x хранения)
- **Mock Video Stream (Debug):** Генератор синтетического видеопотока с искажениями (шумы, glitch-эффекты, повороты) для тестирования

***

## **black_list_bot** (Управление черным списком)

**Назначение:** Администрирование запрещенных слов

**Ключевые особенности:**

- **Секретный ключ доступа:** Авторизация пользователей через секретную фразу перед началом работы
- **Redis хранилище:** Использование Redis SET для хранения списка зарегистрированных пользователей и их добавленных слов
- **RabbitMQ интеграция:** Публикация новых слов в очередь для синхронизации с auto_moderator

***

## **cities** (Поиск городов)

**Назначение:** REST API для автозаполнения и поиска городов

**Ключевые особенности:**

- **Elasticsearch индексирование:** Полнотекстовый поиск с кастомным analyzer для русского языка
- **Трехуровневая стратегия поиска:** Exact match (keyword, boost 10) → Fuzzy match с оператором AND (boost 5) → Fuzzy с fuzziness=2 (boost 0.3)
- **CSV загрузка:** Парсинг и bulk-индексирование городов из CSV при старте с прогресс-логированием
- **Upload endpoint:** Возможность загрузки новых данных городов через REST API
- **Health check:** Эндпоинт для проверки статуса Elasticsearch и количества проиндексированных городов

***

## **shared_models** (Общая библиотека)

**Назначение:** Переиспользуемые модели и схемы для всех сервисов

**Ключевые особенности:**

- **Pydantic модели:** Типизированные схемы для сообщений, результатов модерации, ошибок
- **RabbitMQ схемы:** Определения всех очередей, exchanges, routing keys для межсервисного взаимодействия
- **Enum'ы:** Централизованное определение статусов (MessageState, ModeratorType, ModerationResult)
- **Tortoise ORM конфигурация:** Общие модели БД (User, Message, ModerationLog) и настройки подключения
- **Версионирование:** Отдельные версии пакета с feature flags (`[messaging]`, `[full]`) для минимизации зависимостей
