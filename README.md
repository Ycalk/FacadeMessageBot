# MAX Facade Message Bot

Бот для мессенджера MAX, позволяющий пользователям отправлять сообщения на медиафасад здания. Сообщения проходят многоуровневую модерацию (AI + ручная), после чего отображаются на фасаде, а пользователи получают фото своего сообщения.

## Описание процесса

### 1. Сбор данных от пользователя

Бот последовательно собирает информацию через диалог в MAX messenger:

1. **Текст сообщения** - что будет показано на фасаде (до 80 символов)
2. **Имя автора** - проверяется через белый список и внешний API валидации имён
3. **Город** - поиск через Elasticsearch сервис с поддержкой fuzzy search
4. **Фон креатива** - выбор из доступных вариантов подложек (1-10)
5. **Фото (опционально)** - пользователь может загрузить своё фото, которое сохраняется в MinIO

После подтверждения всех данных сообщение отправляется на модерацию.

### 2. Многоуровневая модерация

#### 2.1 Автоматическая модерация (Mistral AI)

Первый этап - проверка через Mistral AI:
- Анализ текста, имени и города на соответствие правилам
- Проверка на мат, оскорбления, политику, рекламу, спам
- Если **отклонено** → статус `REJECTED`, уведомление пользователю
- Если **одобрено** → отправка на внешнюю модерацию

#### 2.2 Внешняя модерация (Maer API)

Второй этап - отправка на сервис Maer:
- Отправка через REST API (POST `/api/vk/message`)
- Сообщение получает статус `EXTERNAL_MODERATION`
- Ожидание webhook с результатом модерации
- При одобрении → статус `APPROVED`, при отклонении → `REJECTED`

#### 2.3 Резервная модерация (Internal)

Fallback на случай ошибок:
- Если Mistral AI недоступен → статус `INTERNAL_MODERATION`
- Если Maer API недоступен → статус `INTERNAL_MODERATION`
- Ручная модерация через админ-панель NiceGUI

### 3. Отображение на фасаде

После одобрения сообщения:

1. **Показ на креативе** - Maer отправляет webhook (POST `/maer/shown`)
2. **Обновление статуса** - сообщение переходит в `SHOWN_ON_FACADE`
3. **Сохранение метаданных** - время показа фиксируется в БД

### 4. Отправка фото пользователю

Финальный этап:

1. **Получение фото** - webhook от сервиса с URL фото фасада
2. **Скачивание** - загрузка изображения по публичному URL из MinIO
3. **Отправка пользователю** - фото отправляется в MAX messenger
4. **Финальный статус** - `PHOTO_SENT`

### Технологии

- **Backend**: Python 3.13, FastAPI, maxapi (MAX messenger SDK)
- **БД**: PostgreSQL (сообщения), Redis (FSM состояния)
- **Storage**: MinIO (фото пользователей)
- **Search**: Elasticsearch (поиск городов)
- **AI**: Mistral AI (автомодерация)
- **Admin UI**: NiceGUI (панель модератора)

## Flow статусов сообщений

```
CREATED
   ↓
AUTO_MODERATION (Mistral AI)
   ├─ Отклонено → REJECTED
   └─ Одобрено → EXTERNAL_MODERATION (Maer API)
                    ├─ Отклонено → REJECTED
                    └─ Одобрено → APPROVED
```

**Fallback статус**: `INTERNAL_MODERATION` - при любых ошибках автоматической или внешней модерации.

## Webhooks

### Входящие (принимаем)

1. **POST /maer/moderated** - результат модерации от Maer
   - Параметры: `id`, `status` (0/1/2), `reason`
   - Авторизация: header `x-token`

2. **POST /maer/shown** - событие показа на фасаде от Maer
   - Параметры: `id`, `type` (1=shown)
   - Авторизация: header `x-token`

3. **POST /message/shown** - фото фасада от Moder Service
   - Параметры: `message_id`, `frame_url`

### Исходящие (отправляем)

1. **POST {MAER_API_URL}/api/vk/message** - отправка на модерацию
   - Параметры: `id`, `name`, `city`, `text`, `layout`
   - Авторизация: header `x-token`

## Запуск

### Docker Compose (рекомендуется)

```bash
# Скопировать конфиг
cp .env.example .env

# Настроить переменные окружения в .env:
# - BOT_TOKEN (токен MAX бота)
# - MAER_API_URL, MAER_API_TOKEN
# - MISTRAL_API_KEY
# - NAME_API_KEY

# Запустить все сервисы
docker-compose up --build

# Бот будет доступен на порту 8000
```

### Локальная разработка

```bash
# Запустить только инфраструктуру
docker-compose up postgres redis elasticsearch minio cities

# Установить зависимости
cd max_bot
pip install -e .

# Запустить бота
python src/main.py
```

## Конфигурация

### Основные переменные

- `BOT_TOKEN` - токен MAX бота
- `DATABASE_URL` - подключение к PostgreSQL
- `REDIS_HOST`, `REDIS_PORT` - подключение к Redis
- `REDIS_CONTEXT_TTL` - TTL состояний FSM (по умолчанию 7 дней)

### Модерация

- `MISTRAL_API_KEY` - ключ Mistral AI
- `MISTRAL_MODEL` - модель (по умолчанию mistral-small-latest)
- `MAER_API_URL` - URL Maer API для модерации
- `MAER_API_TOKEN` - токен авторизации Maer

### Валидация

- `NAME_API_KEY`, `NAME_API_URL` - API валидации имён
- `MINIMAL_NAME_CONFIDENCE` - минимальный порог уверенности (0.6)
- `CITIES_SERVICE_URL` - URL сервиса поиска городов

### Лимиты

- `MAX_MESSAGE_LENGTH` - максимальная длина текста (80)
- `MAX_NAME_LENGTH` - максимальная длина имени (15)
- `MAXIMUM_MESSAGES_PER_USER` - лимит сообщений на пользователя (2)
- `MESSAGES_TIME_OUT_MINUTES` - таймаут между сообщениями (1 мин)

## Восстановление после сбоев

### Зависшие сообщения

При старте бота автоматически обрабатываются сообщения, зависшие в статусе `AUTO_MODERATION`:

- Поиск сообщений старше 5 минут
- Повторная отправка на модерацию
- Retry механизм с экспоненциальной задержкой (3 попытки)

### Fallback стратегия

При ошибках на любом этапе:
- Mistral AI недоступен → `INTERNAL_MODERATION`
- Maer API недоступен → `INTERNAL_MODERATION`
- Исчерпаны retry попытки → `INTERNAL_MODERATION`

## Админ-панель

Встроенная панель модератора на NiceGUI:

- Просмотр всех сообщений на модерации
- Ручное одобрение/отклонение
- Фильтрация по статусам
- Доступна по тому же адресу что и webhook server

## API эндпоинты

### Публичные

- `GET /message/approved` - список одобренных сообщений (APPROVED + SHOWN_ON_FACADE)

### Webhooks (защищены токеном)

- `POST /maer/moderated` - результат модерации от Maer
- `POST /maer/shown` - показ на фасаде от Maer
- `POST /message/shown` - фото фасада от Moder Service

## Разработка

### Структура кода

```
max_bot/src/
├── main.py              # Точка входа (polling + webhook server)
├── core/                # Конфигурация и логирование
├── db/                  # SQLAlchemy модели и сессии
├── bot/                 # Логика MAX бота
│   ├── instance.py      # Bot и Dispatcher
│   ├── states.py        # FSM состояния
│   ├── routers/         # Обработчики по типам событий
│   └── handlers/        # Обработчики по состояниям FSM
├── api/                 # FastAPI webhooks
│   ├── webhooks.py      # /message/* (старый Moder Service)
│   └── maer_webhooks.py # /maer/* (Maer API)
└── services/            # Утилиты и клиенты
    ├── maer_client.py   # Клиент Maer API
    ├── mistral_moderator.py  # Mistral AI модерация
    └── redis_context.py # FSM context в Redis
```

### Логирование

Все сервисы логируют в stdout с использованием модуля `core.logger`. Логи содержат:
- ID сообщений
- Переходы статусов
- Ошибки с полным traceback
- Метрики времени обработки

### Тестирование

Пока не настроены автоматические тесты. Для ручного тестирования:

1. Настроить `.env` с тестовыми учётными данными
2. Запустить `docker-compose up`
3. Отправить сообщение боту в MAX messenger
4. Отслеживать логи в консоли

## Безопасность

- Все webhook эндпоинты защищены токенами в headers (`x-token`)
- Валидация всех входящих данных через Pydantic схемы
- Санитизация пользовательского ввода (разрешённые символы)
- Rate limiting через лимиты сообщений на пользователя
- Timeout на все внешние API запросы (30 секунд)

## Мониторинг

Ключевые метрики для отслеживания:

- Количество сообщений в каждом статусе
- Время обработки на каждом этапе модерации
- Процент одобренных/отклонённых сообщений
- Ошибки внешних API (Mistral, Maer, Name API)
- Зависшие сообщения (в статусе > 5 минут)
